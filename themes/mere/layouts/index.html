Mere Linux / An introduction

An independent
Linux distribution.

Mere is a musl-based Linux distribution built around its own package manager, written in Zig. Packages are stored independently, system changes are applied atomically, and the underlying mechanisms remain relatively straightforward.

The foundation

Some of the tools and components in use

Mere uses familiar Unix facilities such as directories, symlinks, and user namespaces. The package manager builds on these rather than introducing a separate filesystem model.

01 / The mechanism

How packages are organized

The package manager stores packages as immutable objects and builds system profiles from them. A new system generation can be selected without modifying the packages already in the store.

STAGE 01 / STORE

Packages in the store

Each package is placed in a content-addressed directory. Its files are not changed in place, so different versions can coexist.

02 / The build system

Building packages with Mere

A recipe describes the source, the tools required, and what to produce. Mere assembles those tools into a temporary profile, then runs the build in a separate Linux namespace.

03 / Design choices

Design choices

A few choices shape the package manager and the distribution. Each has benefits and costs, and the implementation continues to change as Mere develops.

01 / IMMUTABILITY

Independent package storage

Packages are stored in separate locations. Different versions can coexist without replacing one another.

02 / ATOMICITY

System generations

Profiles provide system generations that can be activated without rewriting the packages they reference.
